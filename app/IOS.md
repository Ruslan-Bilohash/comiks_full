# 🍎 Комікс·Lab в App Store — покроково

Усе, що можна було зробити без Mac, уже зроблено: вміст застосунку, іконки,
налаштування Capacitor, тексти для крамниці. Лишилося те, що фізично неможливо
на Windows: **зібрати `.ipa` може тільки macOS із Xcode**. Apple не дає іншого
шляху — ні хмарного, ні через Windows.

---

## 0. Що потрібно мати

| | навіщо | ціна |
|---|---|---|
| Apple Developer Program | без нього не можна навіть завантажити збірку | **99 $ на рік** |
| Mac із Xcode 15+ | єдиний спосіб зібрати `.ipa` | свій, позичений або хмарний |
| iPhone | не обовʼязково: перевірити можна в симуляторі Xcode | — |

**Якщо Mac немає — і купувати його не треба.**

> **Про віртуальну машину одразу: ні.** macOS у VM на не-Apple залізі порушує
> ліцензію Apple (система дозволена лише на техніці Apple), а на практиці
> підпис і нотаризація з такої збірки регулярно відвалюються. Це шлях, який
> коштує днів налагодження й може закінчитися блокуванням акаунта розробника.

Робочі варіанти, де Mac не потрібен зовсім:

* **Codemagic** — у проєкті вже лежить готовий `codemagic.yaml`. Він орендує
  справжній Mac mini на час збірки, сам випускає сертифікат через ключ App
  Store Connect API і вивантажує збірку в TestFlight. Усе налаштовується в
  браузері; безкоштовних хвилин на перші релізи вистачає.
* **GitHub Actions** із раннером `macos-14` — те саме, але підпис доведеться
  налаштовувати руками (сертифікат, профіль, секрети).
* **Оренда Mac погодинно** — MacinCloud, MacStadium: віддалений робочий стіл із
  Xcode, кілька доларів на годину.

* **Хмарний Mac за годинами** — MacinCloud, MacStadium. Вистачає кількох годин на
  перший реліз.
* **CI з macOS-раннерами** — GitHub Actions (безкоштовні хвилини для приватних
  репозиторіїв обмежені, але на кілька релізів вистачає) або Codemagic, у якого є
  готовий рецепт для Capacitor. Ключі підпису зберігаються в секретах CI.
* **Чужий Mac на вечір** — достатньо, якщо поруч є знайомий з MacBook.

## 1. На Mac: створити проєкт

```bash
git clone <репозиторій>            # або скопіювати теку проєкту
cd comiks
node tools/build.js                # зібрати сайт
node app/tools/prepare-web.js      # повний офлайн-вміст (див. нижче, чому не --light)
cd app && npm install
npx cap add ios
npx --yes @capacitor/assets generate --ios
npx cap sync ios
npx cap open ios                   # відкриє Xcode
```

### Чому для Apple беремо повний вміст, а не `--light`

Правило App Store **4.2 Minimum Functionality** відхиляє застосунки, які є лише
обгорткою навколо сайту. Офлайн-збірка — це 89 історій, 11 тисяч озвучень, тести
й ігри **всередині** застосунку: він працює в літаку й без жодного запиту в
мережу. Це найсильніший аргумент проти 4.2, і саме його варто подавати першим.

## 2. В Xcode: що заповнити

| поле | значення |
|---|---|
| Bundle Identifier | `com.bilohash.komikslab` (офлайн) або `com.bilohash.komikslab.online` |
| Display Name | `Komiks·Lab` |
| Version / Build | `1.1` / `2` |
| Deployment Target | iOS 14.0 або вище |
| Signing | Team — ваш обліковий запис, «Automatically manage signing» |

### Info.plist — обовʼязкові пояснення доступу

Без них застосунок падає при першому ж зверненні до мікрофона, а Apple відхиляє
збірку ще на завантаженні. Текст має пояснювати **навіщо**, а не що саме:

```xml
<key>NSMicrophoneUsageDescription</key>
<string>Мікрофон потрібен лише для вправ із вимови: ви говорите норвезьке слово, а застосунок порівнює його з еталоном. Записи не зберігаються й нікуди не надсилаються.</string>

<key>NSSpeechRecognitionUsageDescription</key>
<string>Розпізнавання мовлення звіряє вашу вимову зі словом на екрані. Усе відбувається на пристрої.</string>
```

Англійська версія тих самих рядків — у локалізації `en.lproj/InfoPlist.strings`.

## 5. Чого очікувати від перевірки

* **4.2 Minimum Functionality** — головний ризик для будь-якого вебзастосунку.
  Відповідь: офлайн-вміст, 11 тисяч записів озвучення, тести й ігри на пристрої.
* **5.1.1 Збір даних** — онлайн-версія просить пошту; у відповіді вказати, що
  акаунт необовʼязковий і без нього працює все, крім синхронізації.
* **2.1 Повнота** — дати перевіряльнику демо-акаунт у полі «App Review
  Information», інакше вони впруться в екран входу.
* **Контент, створений ШІ** — Apple не забороняє, але це має бути чесно сказано
  в описі. У нас сказано в останньому абзаці.

## 6. Що вже готове в проєкті

* `app/capacitor.config.json` — `appId`, `appName`, кольори, дозволені адреси.
* `app/resources/` — `icon.png`, `splash.png`, `splash-dark.png` для генератора.
* `app/tools/prepare-web.js` — вміст застосунку без сторінок для пошукових систем.
* `app/android_offline/build.js` — офлайн-вміст (той самий, що піде в iOS).
* Переклад інтерфейсу вісьмома мовами — у збірці вже є, окремо нічого не треба.

## 7. Чому в збірці немає посилань на ігри

На сайті є вітрина ігор і посилання на «Двобій 3D» (файтинг, 12+). У збірці для
App Store їх немає: застосунок бачить `window.Capacitor` і не малює ні
категорію ігор, ні сторінку `#/games`, ні смужку в кінці історії.

Причина — **вікова категорія 4+**, яку ми заявляємо. Посилання на бійку з
застосунку 4+ суперечить правилу **1.1.4** (а якщо подаватися в Kids Category —
ще й забороні на будь-які зовнішні посилання без батьківського підтвердження).
Одна кнопка коштувала б переведення всього застосунку в 12+.

Гру варто подавати окремим застосунком із власним рейтингом, якщо колись дійде
до цього.
