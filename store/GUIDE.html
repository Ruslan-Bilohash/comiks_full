0Карта проєкту

Найголовніше: працюємо в корені C:\comiks, а на сервер вантажимо тільки те, що складе tools/build.js у теку dist/. Корінь — це «вихідники», dist/ — «готовий сайт».

ТекаЩо тамЧи вантажимо
assets/Увесь код сайту: app.js, style.css, модулі ігор, дзвінка, парчерез dist/
data/75 коміксів, словники, теми слів, реєстр index.jsчерез dist/
audio/18 198 озвучень (mp3), 158 МБчерез dist/
api/PHP: акаунти, рейтинг, дзвінок, письмочерез dist/ — крім config.php
dist/Готовий сайт: 10 458 файлів, 151,6 МБ✅ це і є те, що вантажимо
app/Мобільний застосунок (Capacitor + Android)ні — з нього виходить AAB
store/Матеріали магазину, знімки екрана, зібрані AAB/APKні
tools/Складання, перевірки, генерація голосу й іконокні
_private/Чернетки та ключ підпису застосунку❌ ніколи
Два файли, які не можна віддати назовні api/config.php — у ньому пароль бази, пошти й ключі оплати. Його немає в dist/ і немає в архіві — це навмисне: коли ви розпаковуєте архів поверх сайту, серверний config.php лишається цілим.
_private/ — там ключ підпису Android. Втратите його — оновити застосунок у Play буде неможливо.

1Щоденний цикл

Чотири кроки, завжди в цьому порядку. Кожен описаний детально нижче.

  1. Змінили щось у assets/ або data/.
  2. Перевірили локально — розділ 2. Сайт відкривається на localhost:8950 одразу, без збірки.
  3. Зібрали — node tools\build.js, далі node tools\audit-all.js має сказати «можна публікувати».
  4. Залили dist/ на Hostinger і перевірили живий сайт — розділи 4 і 5.
Якщо додали нові тексти (репліки, слова, назви) Спочатку треба записати для них голос, інакше на сайті вони будуть німі. Це робить tools\update.bat: перевірка даних → список аудіо → нові голоси → збірка. Один файл замість чотирьох команд. 
cd C:\comiks && tools\update.bat

2Локальна перевірка

Три різні сервери для трьох різних речей. Плутати їх не можна: вони показують різний вміст.

ПортЩо показуєКоли потрібен
8950Сайт з кореня проєкту + робочий PHP-API на SQLiteщодня: перевірка коду, акаунтів, рейтингу
8970Вміст онлайн-застосунку (app/www, 15 МБ)перед збіркою APK
8971Вміст офлайн-застосунку (147 МБ, без сервера)перед збіркою офлайн-AAB

Сайт із живим API

PHP тут потрібен саме тому, що без нього не працюють вхід, друзі, рейтинг і письмо. База — локальний SQLite, живої бази він не чіпає.

cd C:\comiks && php -d extension=pdo_sqlite -d extension=pdo_mysql -d extension=openssl -d extension=mbstring -S localhost:8950 -t C:/comiks

Відкрити http://localhost:8950/. Перевірити, що сервер живий: /api/health.php має відповісти "ok": true.

Вміст застосунку

cd C:\comiks && node app\tools\prepare-web.js --light && node app\tools\serve.js

Відкриється localhost:8970. Якщо чогось не поклали всередину застосунку, сервер надрукує рядок ⚠ немає у застосунку: … — це і є список того, що телефон не побачить без інтернету.

Офлайн-застосунок

cd C:\comiks && node app\android_offline\build.js --serve

Як дивитися «очима телефона»

У браузері: F12 → іконка телефона → ширина 390 × 700. Саме на цьому розмірі перевірені тести й читання коміксів: під час тесту шапка й підвал ховаються, усе вміщається в один екран без прокрутки.

Що перевіряти на телефонній ширині 1) тест: питання + усі відповіді видно без прокрутки; 2) комікс: кадр угорі, репліки гортаються всередині, «Далі» внизу; 3) відповіді-картинки стоять по дві в ряд.

3Збірка сайту

dist/ збирається з нуля щоразу. Руками в ній нічого не правлять — усе затреться наступною збіркою.

cd C:\comiks && node tools\build.js

Що вона робить: складає 10 458 файлів у dist/, дописує SEO-сторінки для 75 коміксів, ставить нову версію у data/index.js і ту саму версію в ім'я кешу sw.js. Завдяки цьому браузер відвідувача підхопить оновлення, а не покаже вчорашню версію.

Перевірка перед публікацією

cd C:\comiks && node tools\audit-all.js

Одна команда перевіряє все одразу: цілість даних, переклади, озвучення (щоб жоден текст не лишився німим), відсутність секретів у збірці, вміст застосунку й матеріали магазину. Публікуємо тільки якщо в кінці:

✅ Усе гаразд — можна публікувати.

Якщо щось не так — вона назве конкретний файл і рядок. Не заливайте, доки не зелено.

Запакувати архів для завантаження

Тільки tar.exe, не «Стиснути» з провідника PowerShell і провідник Windows пишуть у zip шляхи через \. Hostinger такий архів розпакує в один файл із дивною назвою замість тек. Тому пакуємо системним tar.exe — він робить правильний zip.

Архів має містити одну теку comiks/ всередині — саме так, щоб на сервері вийшло public_html/comiks/…:

cd C:\comiks && rd /s /q %TEMP%\klpack 2>nul & mkdir %TEMP%\klpack && xcopy dist %TEMP%\klpack\comiks /E /I /Q /Y >nul && cd /d %TEMP%\klpack && C:\Windows\System32\tar.exe -a -c -f C:\comiks\comiks-update.zip comiks

Перевірити, що всередині саме тека, а не купа файлів:

C:\Windows\System32\tar.exe -tf C:\comiks\comiks-update.zip | more

Перші рядки мають бути comiks/, comiks/index.html, comiks/assets/.

4Заливання на Hostinger

Сайт живе в public_html/comiks/. Архів розпаковується поверх — старі файли замінюються, зайві лишаються.

Через SSH — одна команда (найшвидше)

Доступ уже налаштований у ~/.ssh/config під іменем bilohash, паролів у проєкті немає. Скрипт сам не дасть залити api/config.php і сам перевірить живий сайт після заливання.

cd C:\comiks && node tools\deploy.js

За замовчуванням летить код, дані й сторінки — близько 7 МБ, секунд сім. Озвучення не чіпається: воно змінюється лише разом із новими текстами.

КомандаЩо робить
node tools\deploy.jsкод, дані, сторінки (без аудіо)
node tools\deploy.js --fullте саме разом із озвученням
node tools\deploy.js --only=apiлише вказані теки
node tools\deploy.js --dryпоказати перелік і не заливати
node tools\deploy.js --cleanще й прибрати з сервера робочі теки

У кінці скрипт сам питає живий сайт і друкує, чи збіглися версія даних, кеш sw.js і чи відповідає API. Якщо щось не доїхало — скаже саме це.

Резервна копія перед великими змінами 
ssh bilohash "cd ~/domains/bilohash.com/public_html && tar -czf ~/comiks-backup-$(date +%Y%m%d-%H%M).tar.gz --exclude=comiks/audio comiks"
Виходить близько 27 МБ — усе, крім озвучення, яке й так лежить у проєкті.

Через File Manager (якщо без SSH)

  1. hPanel → Файловий менеджер → зайти в public_html.
  2. Завантажити comiks-update.zip (118 МБ — кілька хвилин).
  3. Правою кнопкою на архіві → Extract → шлях public_html (не public_html/comiks! — тека comiks уже є всередині архіву).
  4. Коли розпакується — видалити сам zip, щоб не займав місце і не лежав у відкритому доступі.

Через FTP (коли інтернет нестабільний)

FileZilla → ftp.bilohash.com → перекинути вміст dist/ у public_html/comiks/. Повільніше (10 458 файлів), зате можна продовжити з місця обриву.

Що НЕ можна робити
  • ❌ Не видаляйте теку comiks/ перед розпакуванням — разом із нею зникне api/config.php, і сайт ляже.
  • ❌ Не заливайте окремо файли з кореня проєкту (C:\comiks\assets\…) — там несклеєні вихідники без версії.
  • ❌ Не кладіть на сервер install.php. Він уже видалений — так і має лишитися.
Коли вантажити не все, а тільки зміни Якщо змінилися лише код і дані (а озвучення — ні), досить залити assets/, data/, index.html і sw.js — це ≈6 МБ замість 118. Але обов'язково разом: версія в data/index.js і в sw.js має збігатися з тим, що в assets/, інакше браузер змішає старе з новим.

5Перевірка після заливання

Чотири перевірки, дві хвилини. Робити щоразу.

1. Сервер живий

Відкрити bilohash.com/comiks/api/health.php. Має бути:

ПолеПравильне значенняЯкщо не так
oktrueдивіться db.hint — там написано, чого бракує
db.oktrue, driver: mysqlперевірити пароль бази в config.php
schema14відкрити будь-яку сторінку сайту — міграція виконається сама
installerвидаленотерміново видалити install.php з сервера
mail.problemsпорожній списоклисти підтвердження не надійдуть — перевірити SMTP

2. Версія оновилася

Відкрити bilohash.com/comiks/data/index.js — у другому рядку "version" має збігатися з тим, що надрукувала збірка.

3. Браузер бачить нове, а не кеш

Ctrl+F5. Якщо сторінка все одно стара: F12 → Application → Service Workers → Unregister → перезавантажити. Ім'я кешу має бути komiks-<версія> — те саме, що у data/index.js.

4. Головне працює

  • Комікс відкривається, звук грає, підказка показує переклад.
  • Тест проходиться до результату.
  • Вхід в акаунт тримається після перезавантаження.
  • На телефоні: тест в один екран, комікс в один екран.

5аДебагер в адмінці

Сторінка 🩺 Діагностика в адмінпанелі відповідає на одне питання: «чи все я зробив правильно?». Вона дивиться на сервер зсередини й ззовні — і каже не лише «так/ні», а що саме виправити.

bilohash.com/comiks/admin.php?p=diag — потрібен вхід адміністратора.

ГрупаЩо перевіряє
🔒 Безпекаінсталятор видалено, права на config.php, довжина секрету, HTTPS, показ помилок PHP, версія PHP, обидва .htaccess, зайві робочі теки, кількість адміністраторів
🌐 Що видно ззовнісправжні запити до сайту: чи закриті config.php, lib.php, api/data/ і вкладення, чи відкривається головна, чи є заголовки безпеки, чи не показується список файлів, чи працює CORS для застосунку
📦 Збіркаверсія, збіг кешу sw.js з даними, наявність кожного файла з реєстру, кількість озвучень і вибіркова перевірка 400 з них
🗄️ Базаз'єднання, тип і версія, схема проти очікуваної, кількість користувачів
⚙️ Службипошта, оплата, право запису в api/data, вільне місце
Найцінніша перевірка — збіг версій Якщо sw.js каже одну версію, а data/index.js іншу, значить залилося не все, і відвідувачі бачитимуть суміш старого з новим. Очима це не помітно — саме тому перевірка є.
Що означають позначки ✅ гаразд · ⚠️ працює, але варто виправити · ⛔ зламано або небезпечно · ➖ не стосується цього середовища (на робочій копії частина перевірок не має сенсу).

Сторінка не показує паролів і ключів — лише «задано / не задано», тож її можна спокійно комусь показати чи зняти на відео.

Окремий JDK ставити не треба Беремо той, що йде з Android Studio. Кожна команда Gradle нижче починається з JAVA_HOME=… саме тому.

Якщо нативного проєкту ще немає

cd C:\comiks\app && npm install && npx cap add android && npx --yes @capacitor/assets generate --android

@capacitor/assets бере app/resources/icon.png і splash.png і розкладає по всіх розмірах. Без цього застосунок матиме стандартну іконку Capacitor.

Далі app/android/local.properties має вказувати на SDK прямими скісними рисками:

sdk.dir=C:/Users/rbilo/AppData/Local/Android/Sdk
Чому саме так З C:\Users\… Gradle падає з незрозумілим Invalid file path — у файлах .properties зворотна риска означає екранування.

Онлайн-версія

cd C:\comiks && node app\tools\prepare-web.js --light && cd app && npx cap sync android
cd C:\comiks\app\android && JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew bundleRelease assembleRelease

Офлайн-версія

cap sync завжди кладе app/www, тому офлайн-вміст підставляємо самі:

cd C:\comiks && node app\android_offline\build.js && rmdir /s /q app\android\app\src\main\assets\public && xcopy app\android_offline\www app\android\app\src\main\assets\public /E /I /Q /Y
cd C:\comiks\app\android && JAVA_HOME="C:/Program Files/Android/Android Studio/jbr" ./gradlew bundleRelease assembleRelease

Готове лежить у app/android/app/build/outputs/, копії з іменами версій — у store/android/build/.

Підпис

Ключ уже створено, build.gradle читає його сам, тому bundleRelease одразу дає підписаний AAB:

_private/android/komikslab-release.jksсам ключ, RSA 4096, дійсний до 2054
_private/android/keystore.propertiesпароль і псевдонім
Збережіть копію обох файлів просто зараз Менеджер паролів або зовнішній диск. Без цього ключа оновити застосунок у Google Play неможливо — доведеться публікувати новий, з нуля, без відгуків і встановлень.

Перевірити, що AAB справді підписаний:

"C:/Program Files/Android/Android Studio/jbr/bin/keytool.exe" -printcert -jarfile C:\comiks\store\android\build\komikslab-offline-1.0.aab

7Тест на телефоні

AAB у Play не встановиш напряму — для перевірки на своєму телефоні є .apk.

  1. Перекинути store\android\build\komikslab-offline-1.0.apk на телефон (кабель, Google Drive, Telegram «Збережені»).
  2. На телефоні відкрити файл → Android спитає дозвіл «встановлювати з цього джерела» → дозволити.
  3. Встановити, відкрити.

Що перевірити першим ділом

  • Іконка й заставка — наші, а не стандартна кулька Capacitor.
  • Звук — відкрити комікс, натиснути 🔊. В офлайн-версії голоси мають бути всередині: увімкніть авіарежим і перевірте ще раз.
  • Тест в один екран — питання і всі відповіді видно без прокрутки.
  • Кнопка «Назад» телефона — повертає на попередній екран, а не закриває застосунок.
  • Онлайн-версія додатково: вхід в акаунт, рейтинг, друзі. Якщо вхід не тримається — це CORS на сервері (розділ 10).
Перевірити ще до складання APK Розділ 2, порт 8971 — там той самий вміст у браузері. Знайти пропущене аудіо чи зламану сторінку там швидше, ніж перевстановлювати APK.

8Google Play — від нуля до випуску

Найдовший крок — не збірка, а анкети. Закладіть вечір на перший раз.

Обліковий запис розробника

  1. play.google.com/console → зареєструватися, одноразово 25 $.
  2. Для особистого акаунта Google вимагає підтвердити особу (документ) і адресу. Займає від години до кількох днів.
  3. Нові особисті акаунти мусять пройти закрите тестування: 12 тестувальників, 14 днів поспіль, і лише тоді відкривається публікація. Починайте цей відлік якомога раніше — це найдовше очікування.

9Оновлення застосунку

Play не прийме другий AAB з тим самим номером збірки.

Перед кожним новим завантаженням підняти versionCode (ціле число, лише вгору) і versionName (те, що бачить людина) у app/android/app/build.gradle:

        versionCode 2
        versionName "1.1"

Далі — звичайний цикл: зібрати сайт → підставити вміст → ./gradlew bundleRelease → завантажити в Play.

Вміст сайту оновлюється без Play Онлайн-версія тягне свіжі комікси з bilohash.com сама. Нова збірка в Play потрібна лише тоді, коли змінився код усередині застосунку або офлайн-вміст.

Play: «Target API level»Google підняв вимогупідняти targetSdkVersion у app/android/variables.gradle
У застосунку німі коміксиу збірку потрапив інший голосовий режимскладальники самі ставлять «жіночий голос»; не правте voiceMode в app/www вручну

Перевірити CORS для застосунку (має бути 204 і access-control-allow-origin: https://localhost):

curl -s -i -X OPTIONS -H "Origin: https://localhost" https://bilohash.com/comiks/api/auth.php
