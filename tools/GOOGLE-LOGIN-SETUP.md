# Увімкнення входу Google для Комікс·Lab

Код готовий, на сервері вхід Google **вимкнено**, доки ви самі не пройдете три кроки нижче. Звичайні способи входу працюють незалежно від нього.

## 0. Спершу — автентифікатор для адміністратора

Ключі Google вводяться в адмінці, тож усе тримається на вході в неї. Увімкніть другий фактор у своєму акаунті на сайті (кабінет → «🔐 Двофакторна авторизація»). Після цього в `admin.php` пароля замало: потрібен ще код із застосунку, а для зміни ключів Google — пароль і **свіжий** код.

## 1. Google Cloud

1. Google Auth Platform → **Branding** і **Audience**: назва Komiks·Lab, домен `bilohash.com`, головна сторінка, сторінки конфіденційності й умов.
2. **Clients → Create client → Web application**. У **Authorized redirect URIs** — рівно:
   `https://bilohash.com/comiks/api/google-callback.php`
   (адмінка показує цю адресу в картці — копіюйте звідти).
3. Scopes лише `openid email profile`. У режимі Testing додайте адреси тестувальників; для всіх — переведіть Audience у Production і виконайте вимоги Google.

Client Secret **не надсилайте** ні в чат, ні в Git, ні в листі — лише вставте в адмінку.

## 2. Адмінка: чернетка → перевірка → увімкнення

`admin.php` → **⚙️ Система** → картка **🔑 Вхід через Google**.

1. **Зберегти як чернетку** — Client ID і Client Secret, ваш пароль, код автентифікатора. Секрет зберігається в MySQL лише зашифрованим (AES-256-GCM); ключ шифрування лежить окремим файлом `/home/u762384583/.komiks-secrets/komiks-secret.key`, поза сайтом. Копія бази без цього файла секрет не відкриває. На сторінку секрет назад не виводиться ніколи.
2. **Перевірити через Google** — відкриє справжню сторінку Google. Увійдіть будь-яким своїм Google-акаунтом. Сервер обміняє код на токен саме цими ключами й прочитає профіль. **Користувача не створюємо, у кабінет не входимо**, лише ставимо позначку «перевірено». Якщо Google відмовить, причину видно в журналі картки (найчастіше — невірний секрет або redirect URI).
3. **Увімкнути** — ще раз пароль і код. Увімкнути можна лише ті ключі, які щойно пройшли перевірку.

Будь-яка зміна Client ID чи секрету повертає ключі в чернетку й **одразу вимикає вхід** — стара перевірка нових ключів не покриває. **Вимкнути** можна будь-коли однією кнопкою, без пароля: це безпечний бік.

## Журнал

Під карткою — журнал адміністратора: входи, невдалі спроби, збереження, перевірки, увімкнення. У ньому ніколи немає паролів, кодів, секретів, токенів чи самого Client ID — лише що сталося й хто.

## Як поводиться вхід

Новий користувач створює акаунт на сторінці реєстрації, поставивши згоду з умовами. Власник наявного акаунта спершу входить паролем або кодом із листа, а потім у кабінеті натискає підключення Google. **Збіг адреси сам по собі не об'єднує акаунти.** Увімкнений другий фактор обов'язковий і після Google-входу.

У вбудованому Android WebView цей вебспосіб прихований; відкрийте сайт у звичайному браузері. Нативний Android-вхід потребує Credential Manager та іншого клієнта.

## Старий спосіб

Блок `google` у `api/config.php` ще працює, але лише доки в адмінці нічого не збережено: ключі з адмінки мають перевагу.

## Перевірки

`bash tools/test-php.sh` — пʼять наборів: токени, Google-вхід, сховище секретів, вхід в адмінку з TOTP, налаштування Google. Справжній обмін із Google перевіряє кнопка «Перевірити через Google» — для неї потрібні ваші ключі.

Документація: [Google OAuth для вебсерверів](https://developers.google.com/identity/protocols/oauth2/web-server), [Найкращі практики OAuth](https://developers.google.com/identity/protocols/oauth2/resources/best-practices).
